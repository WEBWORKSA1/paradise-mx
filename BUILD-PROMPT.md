# Paradise.mx — Concept, Research & Phase-Wise Build Prompt

## 1. The idea (decision)

**Paradise.mx = "Where is Mexico paradise *this* month?"** — a decision engine for Mexico's beaches, islands, cenotes and paradise towns that ranks 38 destinations month by month, then converts the decision into three high-value leads: **trip planning**, **destination weddings / honeymoons**, and **living / buying in Mexico**.

Why this beats the obvious alternatives:

| Option | Verdict | Reason |
|---|---|---|
| Generic Mexico travel blog | Reject | Lonely Planet, Fodor's, Frommer's, AFAR, U.S. News already own "things to do" SEO. No moat. |
| Resort booking clone (CheapCaribbean/Apple/Funjet style) | Reject | Needs inventory, IATA/ARC accreditation, payments, call centre. Thin margin for a solo operator. |
| Expat/relocation-only site | Partial | Mexperience, International Living and Expat.com prove the demand, but traffic is smaller and slower. Kept as one funnel. |
| **Month-by-month "Paradise Finder" + 3 lead funnels** | **Build** | Nobody we read ranks Mexican destinations by month across weather, sea temperature, rain, hurricanes **and sargassum** in one place. "Best time to visit X" and "where to go in Mexico in [month]" are evergreen, high-intent, US/Canada searches that sit right before a booking. |

`.mx` reads as "Mexico", so **Paradise.mx = "Mexico's paradise"** — the domain *is* the positioning.

### Revenue model (assumptions, not promises)

| Stream | Mechanism | Working assumption |
|---|---|---|
| Google AdSense (auto ads) | Travel content, US/CA traffic | Page RPM $12–25 in travel. 100k pageviews/mo ≈ $1.2k–2.5k/mo |
| Trip-planning leads | Sold or referred to vetted travel advisors / DMCs | $15–50 per qualified lead; 0.8–1.5% of sessions convert |
| Wedding & honeymoon leads | Referred to wedding specialists (group room blocks) | $50–150 per qualified couple |
| Live / invest leads | Relocation, residency, real-estate referrals | Referral fees on closed deals; highest ticket, lowest volume |
| Sponsorship & featured listings | Hotels, tour operators, DMCs, wedding planners | $99–499/mo per placement |
| Donations / supporters | Pledges for operations, promotion, hiring, contests | Small but builds community; funds the monthly contest prizes |
| Contests | Photo contest + sponsored prize draws | Email list growth; sponsors fund prizes |

The leverage is the leads, not the ads: 50k sessions/mo × 1% × $30 ≈ $15k/mo of lead value, against ≈ $1–2k of ad revenue at the same traffic.

### Gaps nobody fills (our edge)

1. No site ranks **all** Mexican paradise destinations **by month** with one transparent score.
2. Sargassum, hurricane season and sea temperature are never combined with air temperature and rain.
3. Lead forms are generic; none pre-fill from the visitor's own choices (month, coast, style).
4. Official advisories are scattered; destination pages rarely link the right ones.

## 3. Phase-wise build prompt

Copy each phase into a coding assistant in order. Each phase ends with a check.

### Phase 0 — Ground rules
> Build a static, dependency-free website for **Paradise.mx** that runs on GitHub Pages (free plan) from the `main` branch root. Use HTML, CSS and vanilla JavaScript for the site; Python + Jinja2 only for generating pages. All internal links must be relative so the site works on `username.github.io/paradise-mx/` and on `paradise.mx`. Put the AdSense script exactly as given in every page `<head>`:
> `<script async src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-6620975821265271" crossorigin="anonymous"></script>`
> Add `ads.txt` with `google.com, pub-6620975821265271, DIRECT, f08c47fec0942fa0`. Every page starts with a slim bar reading "Contact, if you are interested in this website/domain name/Sponsorship/Advertisement/Partnership", linked (link text only, URL hidden under the link) to the owner's contact page. Every form posts through FormSubmit's AJAX endpoint to the owner's single inbox, whose address is never written in plain text anywhere: store it as an encoded array in `assets/js/config.js` and assemble it at submit time.
>
> **Check:** a recursive grep for the inbox address or its mail domain returns nothing.

### Phase 1 — Data model
> Create `data/destinations.json` with 38 destinations (Caribbean, Yucatán, Pacific, Oaxaca coast, Baja & Sea of Cortez, highlands). Fields: slug, name, state, region, climate zone, lat/lon, nearest airport (IATA + name), vibes, budget tier, sargassum exposure, Pueblo Mágico flag, summary, highlights, where-to-stay areas, insider tip, optional YouTube id. Create `data/climate.json` with monthly typical high °C, rainy days and sea °C per climate zone plus hurricane and sargassum calendars.
>
> **Check:** every destination has a valid zone and airport; JSON validates.

### Phase 2 — Paradise score
> Score each destination for each month 0–100: air comfort (beach ideal 27–31 °C, highland ideal 21–27 °C), rain-day penalty, sea temperature for swimming, sargassum penalty × exposure, hurricane penalty, bonus for seasonal wildlife events. Publish the formula on the page. Use it in the home-page Finder, the explorer filters, the 38×12 best-time matrix and each destination page.
>
> **Check:** January ranks Los Cabos/Pacific high; June penalises exposed Caribbean beaches.

### Phase 3 — Design system
> Palette: Laguna #0E4D5C, Cenote #19B5A6, Bugambilia #C2255C, Cempasúchil #F2A007, Tinta #10232A, Cal #FFFFFF with Agua #EAF6F4 sections. Type: Bricolage Grotesque for display and UI, Source Serif 4 for long-form reading. One memorable element: the month ribbon that re-ranks destinations live. Original SVG "postcard" art per destination (no stock photos). Sentence case, no all-caps labels, visible focus, reduced-motion support, mobile first.

### Phase 4 — Pages
> Home (Finder, live conditions, top picks, videos, guides, news, plan CTA, support CTA), Destinations explorer + 38 destination pages, Best-time matrix, Plan my trip, Weddings & honeymoons, Live in Mexico, Tools (trip cost, currency, compare, packing list, sargassum outlook), Guides (8 original long-form), Videos, News, Season & festival calendar, Contests, Support (donations), Advertise (sponsorship/partnership + media kit), Careers, About, Contact, Privacy, Terms, Disclaimer (trademark/copyright/affiliate), 404, sitemap.xml, robots.txt.

### Phase 5 — Lead generation (the money pages)
> Multi-step "Plan my paradise" form: where (pre-filled from Finder), when, who, budget, style, services, contact + callback preference + consent. Progress bar, trust row ("free", "no obligation", "reply within 48 h"), sticky CTA on mobile. Inline mini-lead on every destination page. Separate wedding and live/invest forms. Every submission carries source page, chosen month and UTM tags in the subject line.

### Phase 6 — Community & money
> Donations with tiers and an allocation choice (operations, promotion, marketing, hiring, contests & prizes); pledge form now, Stripe/PayPal links later via `config.js`. Monthly photo contest with official rules (no purchase necessary). Careers page with roles and an application form. Advertise page with packages and inquiry form.

### Phase 7 — Self-updating automation
> `scripts/update.py` pulls live weather (Open-Meteo), sea state (Open-Meteo Marine), exchange rates (Frankfurter with open.er-api fallback), travel news (Google News RSS), optional YouTube channel feeds, and recomputes climate normals from Open-Meteo's archive. It then re-runs `scripts/build.py`, which re-renders all pages and the sitemap. `.github/workflows/refresh.yml` runs every 6 hours and commits changes. The browser also fetches live weather and FX directly so pages are current between runs.

### Phase 8 — AdSense readiness & QA
> Original long-form content on every indexable page, About/Contact/Privacy/Terms, cookie notice, no empty ad placeholders (auto ads only until slot IDs are added to `config.js`), fast pages, mobile layout. QA: headless browser pass on every page for console errors, link check, form submit test against a mock endpoint, email-exposure grep, mobile screenshots.

### Phase 9 — Launch
> Push to `WEBWORKSA1/paradise-mx` main. GitHub → Settings → Pages → Deploy from branch → `main` / root. Point `paradise.mx` DNS (A records 185.199.108.153, .109.153, .110.153, .111.153; `www` CNAME `webworksa1.github.io`), add the custom domain in Pages settings, enable HTTPS, then apply to AdSense.
